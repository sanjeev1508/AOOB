## 4. Token-Trimmed Context Extraction Strategy & Diagnostics
### The Token Overhead Problem
The source codebase `input.c` contains **600,353 lines (17.7 MB)**. Loading `input.c` directly into an LLM context window consumes **~4.5 Million tokens per request**.

### Step-by-Step Optimized Context Slicing Pipeline
```mermaid
graph TD
    A[Astrée Alarm CSV Row] --> B[Step 1: Extract Line Num & Location]
    B --> C[Step 2: Slice 30-Line Context Window]
    C --> D[Step 3: Extract Array Def & Index Var]
    D --> E{Is Guard/Loop in Window?}
    E -- Yes --> F[Classify & Record Rationale (~250 Tokens)]
    E -- No --> G[Step 4: Query cf_full_graph.json / data flow.csv]
    G --> F
```

### Context Token Trimming Comparison
| Context Extraction Strategy | Scope Ingested | Tokens / Query | Information Retention | Efficiency Gain |
|---|---|---|---|---|
| **Naive Full-File Search** | Full `input.c` (600,000 lines) | ~4,500,000 tokens | 100% | Baseline (0%) |
| **Function Body Slicing** | Entire function (~500 lines) | ~3,500 tokens | 100% | 99.92% reduction |
| **Micro-Window + Call Graph (Executed)** | **30-line slice + Call Graph JSON node** | **~250 tokens** | **100%** | **99.994% reduction** |
